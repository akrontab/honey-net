# Terraform — Honey-Net Infrastructure

Creates and manages all honey-net cloud hosts on Linode. Each host is a Nanode (1 vCPU, 1GB RAM, $5/mo) running Ubuntu 24.04 LTS.

Servers are driven by `honey-net.json` at the repo root — adding a server entry there is the only change needed before `terraform apply`.

## Repo layout

```
main.tf                    # Provider config + for_each over honey-net.json
variables.tf               # linode_token and region only
outputs.tf                 # server_ips map + root_passwords map (sensitive)
terraform.tfvars.example   # Copy to terraform.tfvars and fill in secrets
.gitignore                 # Keeps terraform.tfvars and state files out of git

modules/
  host/                    # Reusable module — one Linode Nanode instance
    main.tf
    variables.tf
    outputs.tf
```

## Prerequisites

- **Terraform** installed — [developer.hashicorp.com/terraform/install](https://developer.hashicorp.com/terraform/install)
- **SSH key pairs** for each server — path set in `honey-net.json` (`ssh_key` field, private key; `.pub` is derived automatically)
  ```powershell
  ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\log-stack-linode"
  ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\cowrie-linode"
  ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\mysql-linode"
  ```
- **Linode API token** — cloud.linode.com → Profile → API Tokens → Create a Personal Access Token
  Required scopes:

  | Scope   | Permission  | Why |
  |---------|-------------|-----|
  | Linodes | Read/Write  | Create and destroy instances |
  | Events  | Read Only   | Poll operation status (destroy/create completion) |

  Missing the Events scope causes a 401 during `terraform apply` / `terraform destroy` after the operation is initiated.

## First-time setup

```powershell
copy terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars — add linode_token (and optionally region)
terraform init
```

`terraform init` will download the `linode` and `random` providers.

## Usage

```powershell
terraform plan      # Preview what will be created or changed
terraform apply     # Create / update infrastructure
terraform destroy   # Tear down all hosts (prompts for confirmation)
```

After `apply`, run `sync_ips.py` from the honey-net root:
```
cd ..
python sync_ips.py
```

This writes `state.json` so all root scripts (`deploy.py`, `connect.py`, etc.) have the server IPs.

## Adding a new host

1. Add an entry to `honey-net.json` at the repo root with the server name, type, ssh_key, and honeypots.
2. Generate an SSH key pair for the new server (path must match `ssh_key` in the JSON).
3. Run `terraform apply` — the new server is picked up automatically via `for_each`.
4. Run `python sync_ips.py` to add the new server to `state.json`.

No changes to `main.tf`, `variables.tf`, or `outputs.tf` are needed.

## Root passwords

Root passwords are auto-generated by the `random_password` resource and stored in Terraform state. They are only needed for emergency LISH console access — normal access uses SSH keys via Tailscale.

To retrieve a password:
```powershell
terraform output -json root_passwords
```

## State key warning

Servers are keyed by name (`module.host["log-stack"]`). Renaming a server in `honey-net.json` will cause Terraform to **destroy and recreate** that host — it treats it as a different resource. For honeypots this is fine (they are disposable). For backends (log-stack), rename carefully or use `terraform state mv` first.

## State file

Terraform stores infrastructure state in `terraform.tfstate` (gitignored). For a personal PoC, local state is fine. For multi-machine workflows, configure a remote backend in `main.tf`:

```hcl
terraform {
  backend "s3" {
    bucket = "my-tfstate-bucket"
    key    = "honey-net/terraform.tfstate"
    region = "us-east-1"
  }
}
```

## Secrets

`terraform.tfvars` holds the Linode API token — it is gitignored and must never be committed. Root passwords are in Terraform state (also gitignored). The `.gitignore` in this directory protects against accidental commits of `terraform.tfvars`, `.terraform/`, and `*.tfstate`.

## Switching providers

The `modules/host` module wraps a single `linode_instance` resource. To move to a different provider (AWS, Hetzner, DigitalOcean, etc.):

1. Replace the resource in `modules/host/main.tf` with the equivalent resource for the new provider
2. Update the `required_providers` block in `main.tf`
3. Update `variables.tf` if the new provider needs different inputs
4. Module inputs and outputs stay the same — calling code in `main.tf` does not change
