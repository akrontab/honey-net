# Terraform — Honey-Net Infrastructure

Creates and manages all honey-net cloud hosts on Linode. Each host is a Nanode (1 vCPU, 1GB RAM, $5/mo) running Ubuntu 24.04 LTS. Servers are driven by `honey-net.json` — adding a server entry there is the only change needed before `terraform apply`.

## Required Linode API token scopes

| Scope | Permission | Why |
|---|---|---|
| Linodes | Read/Write | Create and destroy instances |
| Events | Read Only | Poll operation status (destroy/create completion) |

Missing the Events scope causes a 401 during `terraform apply` / `destroy` after the operation is initiated.

## State keys — renaming hosts is destructive

Servers are keyed by name (`module.host["log-stack"]`). Renaming a server in `honey-net.json` causes Terraform to **destroy and recreate** that host — it treats it as a different resource. For honeypots this is fine (they're disposable). For backends (log-stack, malware-catalog), rename carefully or use `terraform state mv` first.

## Root passwords

Auto-generated by the `random_password` resource and stored in Terraform state. Only needed for emergency LISH console access — normal access uses SSH keys via Tailscale. Retrieve:
```powershell
terraform output -json root_passwords
```

## State file

Stored locally in `terraform.tfstate` (gitignored). Fine for a personal PoC; configure a remote backend (`s3`, `gcs`, etc.) in `main.tf` for multi-machine workflows.

## Secrets

`terraform.tfvars` holds the Linode API token — gitignored, never committed. Root passwords are in Terraform state (also gitignored). The local `.gitignore` protects against accidental commits of `terraform.tfvars`, `.terraform/`, and `*.tfstate`.

## Switching providers

The `modules/host` module wraps a single `linode_instance`. To migrate to AWS / Hetzner / DigitalOcean:

1. Replace the resource in `modules/host/main.tf` with the equivalent for the new provider
2. Update `required_providers` in `main.tf`
3. Update `variables.tf` if inputs differ
4. Module inputs/outputs stay the same — calling code in `main.tf` does not change
