# Log-Stack

Grafana + Loki log visualization host for the honey-net. Receives logs from honeypots over Tailscale. Grafana is only reachable on the Tailscale network — never the public internet.

## Repo layout

```
deploy/                        # Everything that goes to the server
  docker-compose.yml
  .env.example                 # Template — actual .env is generated by setup.sh
  loki/
    loki-config.yml            # Loki storage, retention, ingestion config
  grafana/
    provisioning/
      datasources/loki.yml     # Auto-provisions Loki as default datasource
      dashboards/dashboards.yml
  setup/
    setup.sh                   # Main provisioning script (9 steps)
    sshd_hardening.conf        # Key-only auth, no passwords
    99-loki-hardening.conf     # sysctl kernel hardening
    fail2ban-jail.local        # fail2ban protecting port 65022

_lib.py                        # Legacy shared utilities (used by connect.py/deploy.py below)
connect.py                     # Legacy — use scripts/connect.py --server log-stack instead
deploy.py                      # Legacy — use scripts/redeploy.py --server log-stack instead
test_loki.py                   # Legacy — use scripts/test_loki.py instead
```

## Deployment

- Target: Linode Nanode (1 vCPU, 1GB RAM), Ubuntu 24.04 LTS
- SSH key: `~/.ssh/log-stack-linode`
- Provision: `python scripts/provision.py --server log-stack` (from repo root)
- Provision: `sudo bash /root/log-stack/setup/setup.sh` on the server
- Connect: `python scripts/connect.py --server log-stack` (from repo root)

Real SSH runs on port **65022**. Port 22 is closed by UFW after setup.

### Prerequisite before running setup.sh

Verify that key-based SSH works **before** running `setup.sh`. Step 4 disables password auth — if your key is not in `~/.ssh/authorized_keys` on the VM you will be locked out immediately.

### What setup.sh prompts for

- Tailscale auth key (`tskey-auth-...`) — generate at tailscale.com → Settings → Keys
- Grafana admin password

### What setup.sh produces

After setup completes it prints:
```
Tailscale IP : 100.x.x.x
Grafana      : http://100.x.x.x:3000  (Tailscale only)
Loki         : http://100.x.x.x:3100  (Tailscale only)
```

Note the Tailscale IP — you need it to configure Vector on the Cowrie host.

## Accessing Grafana

Grafana binds to the Tailscale IP only. You must have Tailscale running on your machine to reach it.

```
http://<tailscale-ip>:3000
Username: admin
Password: whatever you set during setup
```

Useful LogQL queries:
```
{job="cowrie"}               # All Cowrie honeypot events
{job="mysql"}                # All MySQL honeypot events (credentials, queries)
{job="auth"}                 # SSH auth log from honeypot host
{job="syslog"}               # syslog from honeypot host
{job="malware"}              # Malware analyzer results (YARA hits, file types)
```

## Testing the stack

Run from the repo root (Tailscale must be active):

```
python scripts/test_loki.py                          # auto-detects log-stack Tailscale IP from state.json
python scripts/test_loki.py --loki-host 100.x.x.x   # or pass it directly
```

On success it prints HTTP 204 and the exact LogQL query to paste into Grafana Explore:
```
{job="test"}
```

On failure it prints a checklist: local Tailscale status, reachability to the host, whether Loki is running, and whether it's bound to the correct interface.

## Re-deploying after changes

From the repo root:
```
python scripts/redeploy.py --server log-stack   # Uses port 65022 via Tailscale, excludes .env
```

`redeploy.py` rsyncs files from `/root/log-stack/` to `/opt/log-stack/` and runs `docker compose up -d`. The `.env` is preserved.

## Useful server commands

```bash
docker compose -f /opt/log-stack/docker-compose.yml ps
docker compose -f /opt/log-stack/docker-compose.yml logs -f loki
docker compose -f /opt/log-stack/docker-compose.yml logs -f grafana
```

## Known Gotchas

### Grafana and Loki are not behind a firewall — they're bound to Tailscale by design

Docker modifies iptables directly, bypassing UFW entirely. UFW rules on ports 3000 and 3100 would have no effect. Instead, both services bind to `${TAILSCALE_IP}` (not `0.0.0.0`), so the ports are only reachable over the Tailscale interface at the kernel level. If `TAILSCALE_IP` is wrong or unset, the ports fall back to binding on all interfaces and become publicly reachable.

### `.env` is not deployed by provision.py — intentional

`provision.py` excludes `.env` via `shutil.ignore_patterns`. The `.env` is generated by `setup.sh` at provisioning time with the correct `TAILSCALE_IP` auto-detected from `tailscale ip -4`. If you ever recreate the server and the Tailscale IP changes, update `/opt/log-stack/.env` manually and restart the stack.

### If the Tailscale IP changes, the stack needs a restart

`docker compose up -d` reads `TAILSCALE_IP` from `.env` at startup and uses it for port binding. The IP is baked into the running containers. If the IP changes (reissued key, different node), update `.env` and run `docker compose down && docker compose up -d`.

### fail2ban will ban your own IP during setup

`setup.sh` enables fail2ban protecting port 65022. Any failed SSH attempts during debugging will get your IP banned. Symptoms: port 65022 times out from outside but `ssh -p 65022 root@127.0.0.1` works from the Linode LISH console.

Unban yourself:
```bash
fail2ban-client set sshd unbanip <your-ip>
```

### sshd port change requires disabling socket activation (Ubuntu 24.04)

Ubuntu 24.04 runs sshd via `ssh.socket` (systemd socket activation). The socket holds the port binding and ignores the `Port` directive in `sshd_config` — `systemctl restart ssh` alone does not move the port. `setup.sh` disables `ssh.socket` before restarting so the `sshd_config` port takes effect.

If you hit this on an already-provisioned box:
```bash
systemctl stop ssh.socket
systemctl disable ssh.socket
systemctl daemon-reload
systemctl restart ssh
ss -tlnp | grep sshd    # should show 65022
```

### Grafana provisioning permission denied on first start

`cp -r` in `setup.sh` creates files and directories owned by root. Grafana (uid 472)
silently skips all provisioning when it can't read `/etc/grafana/provisioning/` — no
dashboards or datasources appear but Grafana starts cleanly. Symptom: `permission denied`
in `docker compose logs grafana` on the provisioning paths.

`setup.sh` now runs `chmod -R a+rX "${DEPLOY_DIR}"` immediately after `cp`. If you have
an existing server that was provisioned before this fix:

```bash
chmod -R a+rX /opt/log-stack/grafana
docker compose -f /opt/log-stack/docker-compose.yml restart grafana
```

`redeploy.py` also runs `chmod a+rX` after every rsync, so redeployments are not affected.

### Disk usage on a Nanode (25GB)

Loki retention is set to 30 days. On a heavily-attacked honeypot, log volume can be significant. The 25GB Nanode disk is the binding constraint — if Loki fills it, Docker will stop writing and the stack will go unhealthy. Monitor with `df -h` and tune `ingestion_rate_mb` or `retention_period` in `loki/loki-config.yml` if needed.
