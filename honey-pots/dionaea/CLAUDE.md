# Dionaea — SMB / FTP Honeypot Package

Service package for the Dionaea multi-protocol honeypot. This folder is a deployable
unit, not a server — which server(s) it runs on is determined by `honey-net.json`.

## What it captures

- SMB/CIFS connection attempts and exploit payloads (EternalBlue, MS17-010, etc.)
- FTP credential attempts (username + password)
- FTP file transfer attempts; downloaded binaries saved to disk
- Client fingerprints from SMB negotiation handshakes

## Layout

```
deploy/
  docker-compose.yml       # dionaea and vector services
  .env.example             # template — actual .env generated by setup.sh
  dionaea/
    Dockerfile             # builds dionaea from source (Ubuntu 22.04)
    services-enabled/
      smb.yaml             # SMB service — ports 139, 445
      ftp.yaml             # FTP service — port 21
    ihandlers-enabled/
      log_json.yaml        # JSON event log → dionaea.json
  vector/
    vector.toml            # ships dionaea.json + host logs to Loki
  logs.json                # log paths for the metadata addon
  setup/
    fragment.sh            # provisioning steps (appended to server-config/setup.sh)

CLAUDE.md                  # this file
test.py                    # smoke test run from the control machine
```

## Configuration approach

Dionaea is built from source (`deploy/dionaea/Dockerfile`) rather than using the
`dinotools/dionaea:latest` image, which crashes with SIGTRAP (exit 133) on any modern
kernel. The build clones the upstream repo and compiles against Ubuntu 22.04.

Two subdirectories are bind-mounted over the installed defaults:

- `services-enabled/` — overrides which protocol services start (SMB + FTP only)
- `ihandlers-enabled/` — overrides which event handlers run (JSON logging only)

All other config (`dionaea.cfg`, `processors-enabled/`) comes from the cmake install.

The `emu` module (x86 shellcode detection) is disabled at build time via
`-DWITH_MODULE_EMU=OFF` because `libemu-dev` is not in Ubuntu 22.04 repos. This has
no impact on credential/file capture.

**First build takes ~15 minutes on a Nanode** — the cmake compile happens once and is
cached in Docker's layer cache. `redeploy.py` only rebuilds if the Dockerfile changes.

## Protocol and ports

| Port | Protocol | Service   |
|------|----------|-----------|
| 21   | TCP      | FTP       |
| 139  | TCP      | SMB/NetBIOS |
| 445  | TCP      | SMB/CIFS  |

Real SSH is on port 65022 (Tailscale only) — managed by `server-config/`.

## Log paths (on server)

```
/opt/<server>/dionaea/volumes/logs/dionaea.json      # attacker events (JSON per line)
/opt/<server>/dionaea/volumes/logs/dionaea.log       # application log (text)
/opt/<server>/dionaea/volumes/binaries/              # downloaded files
```

Shipped to Loki by Vector with `{job="dionaea"}`.

## Event types in dionaea.json

| type          | Key fields                                      |
|---------------|-------------------------------------------------|
| `connection`  | `src_host`, `src_port`, `dst_port`, `protocol` |
| `credentials` | `src_host`, `protocol`, `login`, `password`    |
| `download`    | `src_host`, `protocol`, `url`, `md5hash`, `sha512hash`, `filelocation` |

Events are written as one JSON object per line (JSONL format).

## Useful LogQL queries

```
{job="dionaea"}                                           # all events
{job="dionaea"} | json | type = "credentials"             # credential attempts
{job="dionaea"} | json | type = "credentials" | protocol = "ftp"  # FTP logins
{job="dionaea"} | json | type = "connection" | protocol = "smb"   # SMB connections
{job="dionaea"} | json | type = "download"                # captured file transfers
{job="auth"}                                              # host auth.log
```

## Known gotchas

### Port 445 conflicts
Ubuntu 24.04 should not bind port 445 by default, but verify before deploying:
`ss -tlnp | grep 445`. If something is listening, identify and stop it before starting
the stack.

### FTP passive mode
Only port 21 (control channel) is exposed. Passive mode data connections (random high
ports) are not configured and will fail. This is intentional — credential capture on
the control channel is sufficient for a honeypot; passive transfers are not needed.

### SMB is very noisy
Port 445 attracts constant automated probes. Log files grow quickly.
Monitor disk: `df -h /opt/<server>/dionaea/volumes`

### Downloaded binaries
Dionaea saves attacker-transferred files to `volumes/binaries/` without the metadata/malware-sender
pipeline (those addons are Cowrie-specific). To scan downloaded files, copy them off the
server and run YARA manually, or submit to a sandbox.
