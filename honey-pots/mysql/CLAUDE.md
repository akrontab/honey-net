# MySQL — Wire-Protocol Honeypot Package

Service package for the MySQL wire-protocol honeypot. This folder is a deployable
unit, not a server — which server(s) it runs on is determined by `honey-net.json`.

## What it captures

- Credential attempts (username + auth)
- SQL queries from automated scanners and human attackers
- Database and table enumeration (`SHOW DATABASES`, `SHOW TABLES`)
- Client library fingerprints via the MySQL handshake

No real MySQL is involved. `server.py` is a pure-Python asyncio implementation
of HandshakeV10 / `mysql_native_password` that accepts all auth and returns
plausible empty result sets.

## Layout

```
deploy/
  docker-compose.yml       # mysql-honeypot and vector services
  .env.example             # template — actual .env generated by setup.sh
  honeypot/
    Dockerfile             # python:3.12-slim
    server.py              # MySQL wire-protocol emulator (asyncio)
  vector/
    vector.toml            # ships mysql-honeypot.json + host logs to Loki
  setup/
    fragment.sh            # mysql-specific provisioning steps (appended to server-config/setup.sh)

CLAUDE.md                  # this file
test.py                    # MySQL connectivity test
```

## Protocol and ports

| Port | Protocol | Goes to           |
|------|----------|-------------------|
| 3306 | MySQL    | Python honeypot   |

Real SSH is on port 65022 (Tailscale only) — managed by `server-config/`.

## Log paths (on server)

```
/opt/<server>/mysql/volumes/logs/mysql-honeypot.json   # attacker events
```

Shipped to Loki by Vector with `{job="mysql"}`.

## Captured event types

| Event         | Key fields                      |
|---------------|---------------------------------|
| connect       | src_ip, src_port                |
| login         | username, database              |
| query         | username, query (full SQL text) |
| use_db        | username, database              |
| change_user   | username                        |
| command       | cmd (byte), arg (raw)           |
| quit/disconnect | username                      |

## Useful LogQL queries

```
{job="mysql"}                                    # all events
{job="mysql"} | json | event = "login"           # credential attempts
{job="mysql"} | json | event = "query"           # SQL queries
{job="mysql"} | json | event = "connect"         # unique source IPs
{job="auth"}                                     # host auth.log
```

## Known gotchas

### Port 3306 is very noisy
Internet scanners probe MySQL constantly. Log files grow fast. Monitor disk:
`df -h /opt/<server>/mysql/volumes`

### Image is built locally — always use --build
Unlike Cowrie (pre-built image), this stack requires `docker compose up --build` to
compile the Python image on the host. `redeploy.ps1` passes `--build` automatically.

### Never run docker compose up --build on the combined stack
The combined compose file includes two services with `build:` contexts: `analyzer`
(cowrie) and `mysql-honeypot`. Running `docker compose up --build` on the top-level
compose starts both builds concurrently, which crashes dockerd with BuildKit error:
`"session healthcheck failed fatally: only one connection allowed"`. This triggers
the systemd restart loop and hits the start-limit.

Build images explicitly in sequence instead:
```bash
docker compose build analyzer
docker compose build mysql-honeypot
docker compose up -d
```
`setup.sh` (via the fragments) and `redeploy.ps1` already do this correctly.
