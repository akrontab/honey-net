# Cowrie — SSH/Telnet Honeypot Package

Service package for the Cowrie SSH and Telnet honeypot. This folder is a deployable
unit, not a server — which server(s) it runs on is determined by `honey-net.json`.

## What it captures

- SSH and Telnet sessions (full PTY interaction)
- Commands executed by attackers
- Malware download attempts (URLs, binaries)
- Attacker SSH public keys (planted in authorized_keys)
- Brute-force credential attempts

## Layout

```
deploy/
  docker-compose.yml       # cowrie + capture-writer + vector services
  .env.example             # template — actual .env generated by setup.sh
  cowrie/
    etc/                   # cowrie.cfg, userdb.txt, authorized_keys
    honeyfs/               # fake filesystem presented to attackers
    txtcmds/               # fake command output files
  vector/
    vector.toml            # ships cowrie.json + host logs + normalised events
  capture-writer/
    Dockerfile             # tiny python:3.12-slim image
    capture_writer.py      # tails cowrie.json, writes per-binary capture sidecars
  setup/
    fragment.sh            # cowrie-specific provisioning steps

CLAUDE.md                  # this file
test.py                    # SSH connectivity and container health test
```

## Protocol and ports

| Port | Protocol | Goes to |
|------|----------|---------|
| 22   | SSH      | Cowrie  |
| 23   | Telnet   | Cowrie  |

Real SSH is on port 65022 (Tailscale only) — managed by `server-config/`.

## Log paths (on server)

```
/opt/<server>/cowrie/volumes/logs/cowrie.json             # attacker session events (JSONL)
/opt/<server>/cowrie/volumes/var/log/cowrie/cowrie.log    # twistd application log
/opt/<server>/inbox/cowrie/                               # captured binaries + .capture.json sidecars
```

Cowrie writes downloaded binaries to `/samples` in the container, which is bind-mounted
from `/opt/<server>/inbox/cowrie/`. The capture-writer sidecar service tails
`cowrie.json` and, on every `cowrie.session.file_download` event, writes
`<outfile>.capture.json` next to the binary with `{src_ip, url, session_id, captured_at}`.
The metadata addon then canonicalises both into `/opt/<server>/inbox/<sha256>` +
`/opt/<server>/inbox/<sha256>.meta.json`.

Shipped to Loki by Vector with `{job="cowrie"}` (raw) and `{job="events", honeypot="cowrie"}`
(normalised).

## Useful LogQL queries

```
{job="cowrie"}                                            # all raw Cowrie events
{job="cowrie"} | json | eventid = "cowrie.login.success"  # successful logins
{job="cowrie"} | json | eventid = "cowrie.command.input"  # commands run
{job="events", honeypot="cowrie"}                         # normalised events for cowrie
{job="events"} | json | event_type = "login"              # logins across all honeypots
{job="auth"}                                              # host auth.log
```

## Normalised event mapping

The cowrie `vector.toml` includes a VRL transform that emits a parallel
`{job="events", honeypot="cowrie"}` stream. Mapping:

| Cowrie `eventid` | `event_type` |
|---|---|
| `cowrie.session.connect` | `connect` |
| `cowrie.login.success` / `cowrie.login.failed` | `login` |
| `cowrie.command.input` / `cowrie.command.failed` | `command` |
| `cowrie.session.file_download` | `download` |
| `cowrie.session.closed` | `session_end` |
| (anything else) | dropped from the events stream |

Success vs failure on login is intentionally collapsed — query the raw stream if you
need that distinction. `payload` carries `input` (commands) or `url` (downloads).
`protocol` is only populated on `cowrie.session.connect` events; downstream events
carry `null` and must be joined on `session_id` to recover protocol.

## Known gotchas

### Mount the full etc/ directory, not individual files
Cowrie declares a Docker VOLUME for `/cowrie/cowrie-git/etc`. Individual file bind
mounts get shadowed by it. Mount the whole directory.

### Cowrie container uid is 999
Volume directories must be `chown -R 999:999`. `fragment.sh` handles this automatically.
The shared inbox subdir at `/opt/<server>/inbox/cowrie/` is `chmod 777` so the
capture-writer (root) and cowrie (uid 999) can both write to it.

### `state_path` is required in cowrie.cfg
Without `state_path = var/lib/cowrie` under `[honeypot]`, auth checking raises
`NoOptionError` and every login fails silently.

### Use `auth_class = UserDB`, not `AuthRandom`
`AuthRandom` ignores `userdb.txt`. Use `UserDB` with `root:x:*` to accept any
password for root.

### Two-stage attack pattern
Attackers often plant an SSH key first, then reconnect with that key for the payload.
Adding planted keys to `cowrie/etc/authorized_keys` captures the stage-2 session.

### JSON log is redirected, twistd log is not
`output_jsonlog.logfile = /cowrie-logs/cowrie.json` writes the JSON event log to the
conventional `./volumes/logs/cowrie.json` host path so `get_logs.py` finds it without
any package-specific config. The twistd application log keeps its default location
under `./volumes/var/log/cowrie/cowrie.log` because nothing downstream consumes it.
